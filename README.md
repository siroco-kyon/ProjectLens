# ProjectLens

既存の C# プロジェクトを会社 PC 上で解析し、Microsoft 365 Copilot に手動で貼り付ける Markdown を生成する Windows / WPF アプリです。ソースコード解析は Roslyn の構文木を使用します。解析時に対象プロジェクトをビルド・実行する必要はありません。

実行時の外部 API、認証、クラウド、テレメトリ、自動更新、Office は不要です。読み込み・解析・プレビューは PC 内で完結します。会社のコードと生成資料を自宅 PC や公開 GitHub に登録しない運用を想定しています。

## 開発環境とビルド

Windows 11、Visual Studio 2026、**.NET デスクトップ開発**ワークロード、.NET 10 SDK を使用します。開発・検証 PC の SDK は **10.0.400** です。`global.json` は 10.0.100 を最低基準とし、`latestFeature` によってインストール済みの安定版 .NET 10 SDK を選びます。ランタイムだけではソースからビルドできません。

```powershell
dotnet --info
dotnet restore ProjectLens.sln --locked-mode
dotnet build ProjectLens.sln -c Release --no-restore
dotnet run --project tests/ProjectLens.Tests -c Release --no-build
dotnet run --project src/ProjectLens.App -c Release --no-build
```

テストは依存ライブラリを増やさないコンソール形式です。`dotnet test` ではなく上記の `dotnet run` を実行します。失敗時の終了コードは 1、成功時は 0 です。

WPF の初期化・架空サンプル解析・資料生成は、開発用 `--smoke-test --sample <絶対パス>` でも確認できます。`--screenshot <新規PNGの絶対パス>` を追加した場合だけ画面画像を指定先へ保存します。実行例は [UI 確認手順](docs/SECURITY-TESTS.md) にあります。

Visual Studio では `ProjectLens.sln` を開き、`ProjectLens.App` をスタートアッププロジェクトに設定してください。通常のビルド・F5 で起動できます。`src/ProjectLens.Core` が解析・コンテキスト生成・出力、`src/ProjectLens.App` が WPF / MVVM、`tests/ProjectLens.Tests` が回帰検証です。

直接使用する NuGet パッケージは Core の **Microsoft.CodeAnalysis.CSharp 5.0.0** のみです。推移的依存を含む確定バージョンは各プロジェクトの `packages.lock.json` で管理します。WPF、ファイルダイアログ、文字コード、テストは .NET の標準機能を使用し、Excel や Microsoft Office のインストールは不要です。ビルド時の NuGet 復元と、アプリ実行時のオフライン動作は別の手順です。

## 使い方

1. `.sln`、`.slnx`、`.csproj` またはプロジェクトフォルダーを指定します。必要なら対象範囲と除外ディレクトリを設定し、解析を実行します。
2. 左のツリーから対象を確認し、中央のクラス・メソッド・プロジェクト参照を検索します。処理中は進捗を表示し、キャンセルできます。構文エラーは診断として表示します。
3. 右のコンテキストで「全体概要」「コード構造」「選択機能」を選びます。機能単位の資料はファイルまたは型を選択して生成します。
4. Copilot への用途、追加の依頼文、分割文字数を指定します。プレビューと文字数を確認してください。ソース本文を含める設定は初期状態でオフです。本文を含める場合は、資料の種類にかかわらず対象ファイル・型のチェックが必要です。
5. 必要なパートだけを明示的にコピー、または指定ディレクトリへ Markdown / テキストとして保存します。Copilot への貼り付け・資料の送信は利用者が行います。

`bin`、`obj`、`.git`、`.vs`、`node_modules`、`packages` は既定で除外します。フォルダー入力は再帰探索し、ソリューション入力はそこに列挙されたプロジェクト、単一 `.csproj` 入力はそのプロジェクトを対象にします。シンボリックリンクなどの再解析ポイントは、意図しない範囲へ進まないよう探索しません。

生成する資料には次を含めます。

| 種類 | 内容 |
|---|---|
| 全体概要 | プロジェクト、フレームワーク、ファイル、主要な型、プロジェクト参照、解析上の制約 |
| コード構造 | 名前空間、using、型、継承・実装、メンバー、引数・戻り値、ファイルパス・行番号 |
| 選択機能 | 選択ファイル・型と、それに関係するファイルの構造。本文は明示選択した定義ファイルだけを任意で追加 |
| 指示文 | 全体理解、特定機能の解析、既存機能の改善、追加時の影響確認、リファクタリング計画、不具合調査 |

長い資料はプロジェクト名・対象範囲・連番を付けて分割します。分割文字数はヘッダー込みの UTF-16 文字数で、画面では 1,000 ～ 100,000 に設定できます（Core API の上限は 1,000,000）。絵文字のサロゲートペアを分断しません。コードブロックがパートをまたぐ場合があります。生成される案内に従って順番に渡し、全パートを渡し終えてから回答を求めてください。Microsoft 365 Copilot の入力容量・社内での取り扱い規則に合わせてサイズを調整してください。

## 初版の解析範囲と制約

Roslyn の**構文解析**が中心です。クラス・インターフェース・record などの宣言、コンストラクター、メソッド、プロパティ、修飾子、引数、戻り値を抽出します。partial の型は各ファイルの宣言として表示されます。UTF-8 / BOM を持つ Unicode ファイルを読み込み、UTF-8 として読めない場合に CP932 を試します。出力は UTF-8 です。

`.csproj` は XML の宣言を直接読むため、MSBuild の評価を実行しません。`Condition`、インポート、変数展開、`Compile Include/Remove`、複数構成、生成コードの実際のビルド対象などを完全には再現しません。プロジェクトフォルダー内の指定拡張子を探索するため、ビルド対象外のファイルも入り得ます。同じディレクトリに複数の `.csproj` がある場合、各プロジェクトの対象ファイルを完全には分離できません。対象範囲・除外で調整してください。プリプロセッサの未指定シンボルにより無効となる `#if` ブロックの宣言は解析結果に現れない場合があります。

`ProjectReference` は**プロジェクトファイルに宣言があること**を確定情報として示します。コード間の型利用・継承・XAML とコードビハインドの関係は構文上の手がかりから推定し、確度と根拠を別に示します。同名型、別名、外部アセンブリなどでは誤推定や未検出があり得ます。コンパイラーの型解決、完全な依存関係、呼び出しグラフ、XAML バインディングの完全解析は行いません。生成資料と元コードを確認して Copilot の提案を判断してください。

WPF の XAML を含めてファイルの役割を整理できます。ASP.NET、Windows Forms のプロジェクト情報も扱える設計ですが、画面イベント・DI・ルーティングなどのフレームワーク固有解析は今後の拡張対象です。大きすぎるファイル・アクセス不能ファイル・構文エラーは診断に残します。再解析ポイントとネットワークパスは安全な対象範囲を維持するため使用しません。

## オフラインで会社 PC に持ち込む

持ち込み対象はこのツールの公開ソース・許可済み依存パッケージ・必要な SDK / ビルド環境、または自宅で作成した配布物だけです。社内で解析したコード・Markdown・ログを自宅へ戻さないでください。依存パッケージや実行物の持ち込みは会社の承認済み手段に従います。

### 社内でソースをビルドする場合

NuGet.org が許可されている PC では通常の `dotnet restore` を実行できます。アクセスできない場合は、許可された接続環境で `scripts/Prepare-Offline.ps1` により必要な `.nupkg` とフィード設定を用意し、会社 PC に持ち込みます。手順と実行例は [オフライン配布手順](docs/OFFLINE.md) にあります。

ローカルフィードを明示して復元する例:

```powershell
dotnet restore ProjectLens.sln --source C:\Approved\ProjectLensFeed --locked-mode --no-cache --ignore-failed-sources
dotnet build ProjectLens.sln -c Release --no-restore
dotnet run --project tests/ProjectLens.Tests -c Release --no-build
```

`--source` を指定して NuGet.org を参照しない復元を行います。ローカルフィードには直接依存だけでなく、ロックファイルに列挙された**推移的依存の全 `.nupkg`** が必要です。SDK の Windows Desktop / .NET ターゲティングパックは SDK・Visual Studio ワークロードで事前に用意してください。オフラインフィードは SDK や Visual Studio の代わりになりません。

### ZIP を展開して使う場合

`scripts/Publish-Portable.ps1` は Release / win-x64 / self-contained のフォルダー配布を作ります。ZIP を会社 PC の許可済みローカルディレクトリへ展開して `ProjectLens.App.exe` を起動します。.NET ランタイムと依存 DLL を含むため、実行先へのランタイム追加インストールを不要にできます。通常のユーザー権限で動き、レジストリー登録やインストーラーは使いません。会社の実行制限や端末のアーキテクチャは別途確認してください。

自己完結配布用のランタイムパックは通常のビルド依存に加えて必要です。会社 PC でオフライン publish を行う場合は、対象 RID のパックも許可済みフィードに準備します。配布 DLL の欠落を避けるため trimming は行いません。

## セキュリティと検証

対象ソースを読む処理と生成資料の保存処理を分離しています。対象プロジェクトの実行・ビルド、ソースの修正、通信、Copilot 呼び出し、認証、バックグラウンド送信は実装していません。通常起動では自動解析・自動コピー・自動保存もしません。指定保存先は解析ルート配下やネットワークパスを拒否し、既存の生成ファイルを上書きしません。プレビュー内のソース本文は「本文を含める」を選んだ場合にだけ生成します。ローカル生成資料にも機密情報が含まれるため、指定先の管理は利用者が行います。

自動テストは構文、型名の曖昧さ、入力形式、範囲、除外、エラー、日本語、CP932、キャンセル、400 ファイル、SHA-256 による元ファイルの不変、資料生成、本文の opt-in、分割の情報保持・文字数、出力制限を確認します。[手動セキュリティ・UI 確認](docs/SECURITY-TESTS.md) に、通信遮断・コピー・出力・UI の確認手順をまとめています。ソースコード検索で通信 API がないことを確認するだけでは、端末全体の通信を証明したことにはなりません。

[架空の WPF サンプル](samples/README.md) を解析して初回の動作を確認できます。会社のコードは回帰テストやサンプルへ追加しないでください。

## GitHub での管理

`.sln`、`.csproj`、ソース、テスト、ロックファイル、ドキュメント、スクリプトを管理します。`bin`、`obj`、`.vs`、配布・オフラインフィードの生成物は `.gitignore` で除外します。実行ファイルを GitHub に公開する必要はありません。

登録先に空のGitHubリポジトリを作成し、実際のURLを指定してソースをpushします。解析対象や生成資料をこのリポジトリへ追加しないでください。

```powershell
git remote add origin https://github.com/<owner>/<repository>.git
git push -u origin main
```

実装時のビルド・検証結果は [検証記録](docs/VERIFICATION.md) にあります。

このリポジトリー自身の利用・再配布ライセンスは所有者が決定してください。解析対象のソースや生成物に、このツールから新たなライセンスを付けることはありません。依存ライブラリの通知は [THIRD-PARTY-NOTICES](docs/THIRD-PARTY-NOTICES.md) と `docs/licenses/` に保存し、ZIP 配布にも含めます。パッケージの同梱情報も確認してください。
