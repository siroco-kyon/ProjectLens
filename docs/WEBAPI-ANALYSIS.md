# WebAPI の接続設定と通信処理

接続先の変更を調べるときに、「どこで URL を設定し、何を送って、応答をどう使うか」を確認するための構文解析です。解析対象のプログラムを実行せず、通信もしません。

## 画面での確認

1. 通常どおり解析を実行して、中央の「WebAPI」タブを開きます。
2. 「呼び出し・処理」で HTTP メソッド、接続先・パスの式、呼び出し元と根拠のファイル・行を確認します。
3. 呼び出しを選ぶと、送信データ、応答の型・読み込み、その応答を使う同じメソッド内の処理候補を確認できます。
4. 「接続設定」で設定ファイルの記述、`BaseAddress` の設定、コードからの設定参照を確認します。
5. 必要なファイルを資料の対象に追加し、「C. 選択ファイル・型の解析」で資料を生成します。設定ファイルも含めたい場合は、そのファイルを明示選択します。

解析結果の検索は WebAPI の情報にも適用します。検索は表示を絞るだけで、資料の対象を変えません。入力・除外・解析範囲を変えると結果を無効化するため、再解析してください。

## 抽出する内容

| 観点 | 対象 |
|---|---|
| 接続設定 | JSON／XML（`.config`・`.settings` を含む）の接続先候補、C# の `BaseAddress`、構成値・環境変数などへの参照 |
| 通信 | `HttpClient` 系の GET／POST／PUT／DELETE／PATCH、JSON 拡張メソッド、`HttpRequestMessage` を使う `SendAsync` |
| 送信 | 接続先・パスや送信データの式。動的な式は実際の値へ展開しない |
| 応答 | JSON 読み込みなどの型・式と、取得した変数を利用する処理の候補 |
| エラー等 | ステータス判定、成功確認、例外処理、認証ヘッダー設定の記述 |
| 根拠 | ファイル、呼び出し元の型・メソッド、行番号、確度 |

設定ファイルの値は「記述を確認」、コードから拾う呼び出しと処理は「構文上の候補」として扱います。いずれも実行時にその設定が有効になるかは未評価です。同名の独自クラス・メソッドや変数の再代入では誤推定があり得ます。

## Copilot 用資料

全体概要には接続設定と通信の一覧を載せます。コード構造・選択機能の資料には処理候補の詳細も載せます。選択機能の資料は、選択と関連補足で得たファイルの範囲に限定します。設定と呼び出しの対応を自動確定したり、範囲外の設定ファイルを読み足したりしません。

本文の設定をオフにしても、URL、設定キー、送信・応答の式の要約は含まれます。認証ヘッダーの値や機密キーは要約から伏せます。これはすべての機密情報を除去する機能ではありません。「ソース本文を含める」を明示的に有効にすると、選択したファイルの元の本文を加工せずに載せます。

依頼文の例:

> 接続先 WebAPI を変更する予定です。接続設定、送信項目、応答の読み込みと利用、エラー処理を根拠付きで整理し、変更候補と追加確認が必要な箇所を挙げてください。

## 解析の限界

環境変数・配布先・外部サービスで決まる実際の URL、設定の優先順位、認証の有効性、DI・共通ハンドラーの適用は評価しません。別メソッド、画面、サービスまでの完全な処理追跡や、業務の意味の自動判定も行いません。クライアントの型は同じファイルの宣言を手がかりにするため、partial の別ファイルや基底クラスで宣言されたクライアント、独自の API ラッパー、型の別名などは検出できない場合があります。複数の API 呼び出しやネストした関数は分けて扱いますが、応答変数の別名や複雑なデータフローは未解決のまま残る場合があります。未検出は通信や処理が存在しないことを保証しません。

`samples/FictionalOrders` の `OrdersApiClient.cs` と `appsettings.json` で、架空の接続設定・注文検索・登録の解析を確認できます。
