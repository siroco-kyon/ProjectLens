# 設計と拡張

## 構成

```text
ProjectLens.App (WPF / MVVM)
  View          画面、進捗、プレビュー
  ViewModel     操作・検索・選択・資料生成の状態
  Services      ファイル選択と明示的なクリップボード操作
       ↓
ProjectLens.Core
  Analysis      ローカル範囲の発見、XMLメタデータ、Roslyn構文解析、関連候補
  Models        解析結果と生成条件
  Context       Markdown、用途別指示文、文字数上限付き分割
  Export        指定先への明示保存、対象ソース・既存ファイル保護
       ↑
ProjectLens.Tests (追加NuGet不要のコンソール検証)
```

CoreはWPFに依存しません。`IProjectAnalyzer`を差し替えれば、将来の意味解析エンジンや別の入力形式を追加できます。画面のファイル選択とコピーは`IUserInteraction`で分離しています。

## データの流れ

利用者がローカル入力と対象範囲を指定すると、解析エンジンが読み取り専用でファイルを列挙します。csprojやslnxのXMLは宣言を読み取るだけで、MSBuild、Import、Task、対象プログラムのコードは実行しません。

ソース本文と構造はメモリ内に保持します。資料生成はそのスナップショットを使うため、生成時に別のファイルや後から変更された本文を読み直しません。本文の出力は初期状態で無効です。WPF画面では本文を含める際にファイル・型の明示選択を要求します。

解析条件を変更すると以前の解析結果を無効化します。資料条件や選択を変更するとプレビューを無効化し、コピー・保存には再生成が必要です。役割メモはメモリ内に保持し、解析対象へ保存しません。

選択機能の資料では、関連補足を「選択のみ・参照先・参照元・両方向」と最大1〜3段で指定します。初期値は両方向・1段です。関係の起点から関連先へ進むのが参照先、逆に進むのが参照元で、XAMLの対応関係もこの方向で扱います。解析済みファイルだけを対象に幅優先でたどり、選択ファイルからの最短段数を記録します。循環や重複は範囲を広げず、未解析ファイルやプロジェクトファイルを経由して探索しません。

生成資料には明示選択と自動補足を区別した一覧を付けます。選択機能の関係表は両端が対象範囲にある関係だけを載せます。プロジェクト構成・参照宣言は全体情報として残します。補足したファイルのソース本文は自動では含めず、本文を出すにはファイルまたは型の明示選択が必要です。補足の方向・段数の変更もプレビューを無効化します。

資料はまず画面に表示します。コピーは表示中の1パート、保存は生成済みの全パートを対象にします。保存先はローカルディスク上の解析ルート外とし、ネットワークパスとリンクを拒否します。保存ごとに別のファイル名を使い、既存ファイルを上書きしません。途中失敗時は今回の保存で作成したファイルのみ削除します。

## 関係の確度

`Confirmed`はProjectReferenceがXMLに書かれている事実を表します。条件付き参照が現在のビルドで有効かどうかは未評価です。`Inferred`は型名、継承構文、型の使用箇所、XAMLのクラス名から得た候補です。名前だけで意味的な依存関係を確定しません。

完全な依存関係、メソッドの呼び出し先、DI、動的生成、リフレクション、バインディング経由の関連は初版の対象外です。複数の候補がある場合は診断で確認を促します。XMLや構文エラー、読み取り不能、範囲外の参照は診断として表示します。

## 次の拡張候補

1. 利用者が指定した参照アセンブリだけを使うRoslyn意味解析。
2. 同一型のpartial宣言をまとめた表示と、XAMLバインディングの補足。
3. 構成別のプリプロセッサシンボル、明示的なCompile項目設定。
4. 依存グラフの可視化と、関係を限定して追加する選択UI。

意味解析を追加する場合も、対象csprojを無条件にMSBuildへ渡すと外部Taskや復元が実行される可能性があります。構文解析と同じ読み取り範囲・通信禁止の条件を維持する設計が必要です。
