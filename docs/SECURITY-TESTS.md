# 手動セキュリティ・UI 確認

会社のコードを使わず、`samples/FictionalOrders` と検証用のローカルディレクトリで実施します。会社へ持ち込む Release / self-contained 配布物でも同じ手順を実行してください。

## 自動検証

```powershell
dotnet build ProjectLens.sln -c Release --no-restore
dotnet run --project tests/ProjectLens.Tests -c Release --no-build
```

コンソールにすべて PASS と表示され、終了コードが 0 になることを確認します。テストは一時ディレクトリへ架空ファイルを生成し、解析前後の SHA-256 を比較します。Microsoft Office は使いません。

## 開発用の WPF 起動検証

`.NET 10 SDK` で Release ビルドした後、実際の WPF 画面初期化・サンプル解析・資料生成を、表示を隠した起動で確認できます。終了コードは成功時 0、失敗時 1 です。コピー・Markdown 保存は実行しません。会社のコードの代わりに架空サンプルを使います。

```powershell
$samplePath = (Resolve-Path .\samples\FictionalOrders\FictionalOrders.sln).Path
dotnet run --project src/ProjectLens.App -c Release --no-build -- --smoke-test --sample $samplePath
```

画面の PNG が必要な場合は、解析ルートの外にあるローカルディレクトリと、まだ存在しない `.png` の絶対パスを明示します。次の例は利用者の一時フォルダーを使います。

```powershell
$samplePath = (Resolve-Path .\samples\FictionalOrders\FictionalOrders.sln).Path
$screenshotDirectory = Join-Path $env:TEMP 'ProjectLens-Screenshots'
New-Item -ItemType Directory -Path $screenshotDirectory -Force | Out-Null
$screenshotPath = Join-Path $screenshotDirectory ('ProjectLens-' + [Guid]::NewGuid().ToString('N') + '.png')
dotnet run --project src/ProjectLens.App -c Release --no-build -- --smoke-test --sample $samplePath --screenshot $screenshotPath
```

配布物でも `ProjectLens.App.exe` に同じオプションを渡せます。保存先のネットワーク・リンク・解析ルート配下と既存ファイルは拒否します。PNG は `--screenshot` を明示した場合だけ生成します。診断画像には資料プレビューが写るため、会社で使う場合は指定先を会社 PC 内に限定してください。これは開発用の明示操作であり、通常起動ではサンプル解析・画像保存を自動実行しません。

この起動検証は WPF の初期化と処理経路の確認です。キーボード操作やクリップボード競合、見た目の確認は、下記の手動検証も実施してください。

## オフライン実行

1. 必要なビルド・publish を接続可能な許可済み PC で完了します。
2. テスト PC のネットワークを無効にするか、承認された手順で当該 exe の外向き通信を遮断します。
3. ZIP 展開した exe を通常のユーザーとして起動し、サンプルの読み込み、解析、資料生成、プレビュー、Markdown / txt 保存を実行します。
4. 認証・更新要求・外部接続エラーが発生せず処理が完了することを確認します。
5. 必要に応じて会社で許可された監視ツールで、ProjectLens プロセスの外向き通信がないことを確認します。ブラウザーや Visual Studio 等の他プロセスの通信と区別してください。

復元をオンラインで行うことと、配布したアプリが実行時に通信することは別です。アプリから Copilot を起動・送信する機能はありません。

## ソース変更・対象範囲

1. 検証用コピーのソースツリーでファイル一覧、内容のハッシュ、タイムスタンプを記録します。
2. 除外するサブフォルダーと `bin`、`obj`、`.git`、`.vs` に識別しやすい架空 C# ファイルを置きます。
3. フォルダー全体と限定した範囲を別々に解析し、除外したファイルや選ばない範囲が一覧・コンテキストに入らないことを確認します。
4. 解析・プレビュー・コピーの前後で元ソースの一覧・ハッシュが同じことを確認します。
5. 保存先に解析対象配下・UNC パス・再解析ポイントを指定し、保存されないことと利用者にエラーが表示されることを確認します。

## コピーと本文の選択

1. クリップボードへ機密性のない識別テキストを入れます。
2. アプリを起動・解析・資料生成します。コピーを押す前に他アプリへ貼り付け、元の識別テキストのままであることを確認します。
3. 初期設定でプレビューにソース本文が入らず、構造情報だけが表示されることを確認します。
4. 「本文を含める」を明示的にオンにし、選択機能では選択ファイルの本文だけが含まれることを確認します。関連ファイルの全文を自動的に追加していないことも確認します。
5. 指定パートのコピーボタンを押した後、そのパートだけが貼り付くことを確認します。クリップボード競合時は UI にエラーが表示されることを確認します。

コピーした資料は OS のクリップボード履歴・同期機能の管理対象になり得ます。会社の規則に応じて OS 設定を管理してください。アプリ自身は履歴・同期・送信を実装していません。

## 出力と分割

1. 空の許可済みローカル出力フォルダーを指定し、`.md` と `.txt` の両方で保存します。
2. 保存された本文がプレビューと一致し、UTF-8 の日本語や絵文字が正しく読めることを確認します。
3. 同じ保存を再度実行し、最初のファイルが変更されないことを確認します。エラーまたは別名保存を利用者が確認できる必要があります。
4. 分割文字数を 1,000 に設定し、各パートにプロジェクト名・範囲・連番があること、ヘッダー込みで上限を超えないことを確認します。
5. `<!-- CONTEXT BODY -->` より後ろの断片をパート順に連結し、未分割の資料と一致することを確認します。追加の改行を挿入しないでください。

## UI・エラー・キャンセル

1. ファイル・フォルダーダイアログ、ツリー、クラス・メソッド検索、プロジェクト参照、6 用途の指示文を操作します。
2. 構文エラーを含む架空 `.cs`、日本語パス、CP932 ファイルを読み込みます。解析の残りは継続し、診断が表示されることを確認します。
3. 大量の架空ファイルを解析し、進捗が更新され UI が応答することを確認します。途中でキャンセルし、状態が戻り、再度解析できることを確認します。
4. 読み取り不能なパスや削除されたファイルを指定し、アプリが異常終了せずエラーを表示することを確認します。
5. Windows の表示倍率 100% / 150%、ウィンドウ縮小、キーボード Tab 移動でも主要操作と文字が読み取れることを確認します。

この文書は検証手順です。自動化されていない項目の実施結果は、実際に操作して確認したものだけを記録してください。
